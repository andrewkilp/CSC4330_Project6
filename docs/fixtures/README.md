## Shape

```
{ scenario, description, seed, fictional: true,
  expected: { operator_inputs: [{kind: instruction|approval, response_id, text?, reason}],
              unanswered_questions: [...], outcome },
  events: [ durable event envelopes from docs/contracts.md ] }
```

`events` uses the planned envelope `{id, call_id, seq, type, occurred_at, context_revision, payload}`. Business turns stream partial updates under one turn id before the final text. Responses follow generating -> suggested -> approved -> speaking -> spoken; assistant turns appear only after the spoken acknowledgement. An operator instruction emits `instruction.updated` pending at revision N, cancels the waiting suggestion at N, then applies at N+1. Usage is a zero-cost `estimate_only` mock value. The summary follows the ended call.

## Guarantees

- The same seed produces byte-identical, identically ordered events. A different seed changes identifiers and timing jitter, never the script.
- Each lifecycle and response step is driven through `packages/go/conversation`, so the fixtures contain only transitions the state machine accepts.
- `mock.Validate` rejects gaps, duplicates, backward time or revision, illegal transitions, edited final turns, unsupported evidence, non-fictional numbers, unlabelled businesses, real mode, and fixtures missing an unanswered question or an operator instruction. Errors name the event seq and field.
- These are scenario scripts, not provider adapters (#6) or the event reducer's own fixtures (#9).
